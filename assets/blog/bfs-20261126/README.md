## verify_code.py 的设计

**代码来源：从文章正文的正则抽取，不另存副本。** 门里的
`extract(src, lang)` 抓的是 `^```python` / `^```cpp` 围栏，所以文章改了代码、
门就跟着改，不存在「门和正文各有一份、慢慢跑偏」的问题。
围栏数量不等会直接判红（本系列踩过：把不可运行的片段标成 `python` 导致
`python/cpp blocks unequal: 11 vs 9`——片段不是程序，不该冒充代码块）。

**两种语言都必须真跑。** 只跑 Python 会让「C++ 侧写错」完全漏掉，
而本文恰好有两个只在 C++ 上暴露的坑（`for (int i = 0; i < q.size(); i++)`
在循环体里 push 会重新求值 `q.size()`）。C++ 侧用
`g++ -std=c++17 -Wall -Wextra -Werror -O1` 编译，**零警告**才算过。

**两侧跑同一批固定种子用例**，逐行对拍输出（726 行）。随机源是门自己实现的
LCG（`Lcg`），不是 `random`，这样 Python 与 C++ 能拿到**逐字节相同**的用例。
`SEED = 20261126`。

### 外部参照：不能只跟自己比

「Python 跑出来的等于 C++ 跑出来的」只证明两种语言**一致**，不证明**正确**。
所以每一类题都配了一个独立参照：

| 题目 | 参照怎么来的 |
|---|---|
| 773 滑动谜题 | 先从目标态反向 BFS 建**精确距离表**，再逐局面比对 |
| 773 不可达局面 | `6! = 720` 个排列里另一半（换位奇偶性不同）必须返回 `-1` |
| 752 转盘锁 | 朴素的单源 BFS 参照 |
| 1091 二进制矩阵最短路 | 先建**显式八连通图**，再跑标准 BFS |
| 994 腐烂的橘子 | **逐分钟暴力模拟**，不依赖任何 BFS |
| 542 01 矩阵 | **每个格子单独做一次 BFS**（慢，但显然对） |
| 127 单词接龙 | 朴素建图 + BFS |
| 841 钥匙和房间 | DFS 可达性 |

### 反向对照：证明门真的会红

一组「能通过」的门和一个**坏掉的**门在输出上可能一模一样。所以门里内置了
5 个**故意改坏**的实现，要求每个都必须被抓到：

| 改坏的地方 | 坏版本 | 正确版本 | 判定 |
|---|---|---|---|
| `visited` 出队才标记 | 队列峰值 8505 | 1063 | 坏 > 正确×5 |
| 994 的 `minutes` 无条件 +1 | 2 | 1 | 坏 > 正确 |
| 1091 退化成四连通 | 3 | 2 | 坏 ≠ 正确 |
| 994 只从一个源出发 | 9 | 5 | 坏 ≠ 正确 |
| 行内排序把不同解看成相同 | True | False | 坏 ≠ 正确 |

**这里有一个必须记下来的教训。** 994 那条一开始用的探测用例是 `[[2, 0]]`
（一个腐烂橘子、一个空格），两边都返回 `0`，**门抓不到**。原因是正确实现在
`fresh == 0` 时提前 `return 0`，坏实现走的是同一个提前返回。
必须让**最后一轮「展开了节点却没有新鲜橘子被传染」**才会多算一分钟；
穷举 1×2 起的所有形状后，最小反例是 `[[1, 2]]`（正确 1 / 坏 2）。
判定条件后来也从 `bad_v != good_v` 收紧成 `bad_v > good_v`——
如果哪天门和坏实现**同时**失效、两边都返回 0，`!=` 会静默放过，`>` 不会。

### 边界覆盖

空表、单节点、两节点、全相等值、负数、退化形状（左深链 / 右深链 / 完全二叉树 /
随机）、`k = 1` / `k = n` / `k > n` / `k = 0`、`target` 落在 `deadends` 里、
「全是腐烂橘子」、存在隔离的新鲜橘子（返回 `-1`）。

发现的，`Check` 一个都没报：

2. 图 2 层说明行贴住节点 B/D 的圆圈（bbox 检查通过，肉眼不过）
3. 图 3 两条图例掉在面板圆角框外（面板高度 430 → 460）

## 一个卡了 20 分钟的坑：生成器写得慢 ≠ 算法很慢

门曾经整跑 20 分钟零输出。分段计时后 `build_cases()` 只用 **4.7 秒**，
真正的死循环在阶梯词生成那一段：

```python
alpha = "ab"; L = 3
pool = set()
while len(pool) < 6:                      # 永远出不来
    pool.add("".join(alpha[rng.below(len(alpha))] for _ in range(L)))
```

枚举空间只有 `2^3 = 8` 个词，而 LCG 是确定性的，会反复吐同样的词。
**用「拒绝采样」凑集合之前，先确认枚举空间比目标规模大一个数量级。**
已改成枚举全部 8 个词、用同一支 LCG 做 Fisher-Yates 洗牌后取前 6 个。

定位手段值得记：给 `sys.settrace` 加一个**逐行执行计数**，超过预算就抛异常，
再打印最热的几行。这样 3.7 秒就指到了具体行号，而干等 20 分钟什么都得不到。
